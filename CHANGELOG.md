# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project intends to follow [Semantic Versioning](https://semver.org/) once it reaches `1.0.0`.

## [Unreleased]

### Added

- Full ADR lifecycle: `init`, `new`, `approve`, `reject`, `undo`, `supersede`, `version`, `revise`.
- `migrate` — adds an adrpy-compliant header to existing, hand-written decision files.
- `explore` — best-effort listing of every decision file in a repository.
- `config` — reads or updates an existing repository's own `adr-config.adrplus`.
- `installconfig` — per-user, install-level default configuration, seeding new repositories and supplying a `migrate` fallback for `migrationpattern`.
- `log` — writes a decision-log entry, the lighter-weight sibling of a formal ADR (see [ADR003](doc/adr/ADR003V01-decision-log-entries-separate-human-reviewed-judgment-from-tool-executed-mechanics-via-a-future-adrpy-log-command.md)).
- `supersede --title` — optionally gives a successor its own title instead of always carrying the predecessor's own forward.
- `folderlog` — the decision-log directory is now an independently configurable, recursively-scanned `adr-config.adrplus` field, decoupled from `folderadr` (see [ADR007](doc/adr/ADR007V01-decision-log-directory-becomes-an-independent,-recursively-scanned-config-field-instead-of-a-fixed-sibling-of-folderadr.md)).
- A single, central `FailureCodes` registry for every failure code this tool can return, replacing scattered string literals (see [ADR005](doc/adr/ADR005V01-failure-codes-and-shared-constants-gain-dedicated,-closed-registry-classes.md)).
- A structured `failure_codes` field on every command's `describe()` response, listing every failure code that command can actually return with a one-line condition each — the same information `doc/commands/*.md`'s own new "Failure codes" table shows, now also machine-readable in the live JSON contract (see [ADR008](doc/adr/ADR008V01-describe()-gains-a-structured-failure-codes-field,-sourced-from-shared-per-module-dictionaries-for-universally-reachable-codes.md)).
- A repository-wide lock covering the full critical section of every mutating command, with a documented failure boundary (see [ADR001](doc/adr/ADR001V01-repository-lock-covers-the-full-critical-section-of-every-mutating-command.md)).
- `adrpy-skills` — a separate console script, shipped in the same distribution, that installs the `decision-log`/`pre-release-audit`/`comment-audit` judgment-layer skills for Claude Code, Cursor, GitHub Copilot, and a generic `AGENTS.md`, split by each provider's own activation model (full body vs. a short stub plus one shared doc). Every write is protected by a content-hash drift marker (`install`/`remove`, `--force` to override; `list` reports the same marker read-only, with no `--force`); never called by `adrpy` itself (see [ADR009](doc/adr/ADR009V01-ai-coding-agent-skills-installer-ships-as-a-separate-adrpy-skills-entry-point-with-per-provider-full-body-or-stub-delivery.md), [`doc/skills/`](doc/skills/README.md)).
- Public project scaffolding: `LICENSE` (MIT), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, this changelog.
- `supersede --resume` — finishes an interrupted `supersede` onto the successor it already created, or adopts a supersede chain `migrate` brought in (both files migrated placeholders). Without it, an existing successor pointing back at the decision is refused with `supersede-successor-already-exists` instead of being guessed at.
- `supersede` counts a file as a decision's existing successor only when its sequence number is higher than the decision's own; a file pointing back from the same or a lower number (itself, its own family, a hand-made cycle) is ignored. `reject` on a successor whose predecessor's family has no member marked `Superseded` has nothing to revert and just rejects it; when a member of that family has a header that does not parse, `reject` refuses and names the file (`data.unparseable_files`) instead of assuming nothing is marked.
- `adrpy-skills`: in `AGENTS.md`, a block indented four spaces or more (or by a tab) counts as the tool's only when its marker hash still matches -- `install` then updates it in place, and `remove` deletes it only with `--force` (reason `indented`); any other indented copy is left untouched and a new block is appended with a warning. Any number of leading BOMs is tolerated, a block indented as a list item is recognized, a new shared doc is written only when a stub will be, and `remove` no longer reports a shared doc as kept when it does not exist.
- One rule for invalid decision files (see `doc/lifecycle.md`): the filename decides identity and numbering, counting every file; the header decides status, counting only headers that parse. A file whose header does not parse is left out of every family rule and reported in `warnings` (`<file>: ignored -- its header does not parse (<reason>)`) instead of failing the command (`family-scan-unreliable-encoding` and `migration-scan-unreliable-encoding` are gone); `explore` shows each file's `header.state` and `header.invalid_reason`; a command aimed at one says why in `detail`. Two writes still refuse rather than guess: `reject` when it cannot find the predecessor by its back-reference and any file of the predecessor's family does not parse, and `supersede` when a file pointing back does not. `version`/`revise` refuse with `file-already-exists` when the number they would create is already held by any file of the family -- one whose header does not parse, or one whose title was edited so its filename differs. An interrupted `migrate` names the files already migrated in `data.results`.
- A decision an editor saved with a BOM (PowerShell 5.1 `-Encoding UTF8`, some editors) is read normally; the next rewrite drops the BOM.
- `migrate` never writes a second header over a damaged one: a file carrying this tool's header that does not parse refuses the whole run (`migration-invalid-headers-exist`, `data.files`).
- `migrate` reports `migrationpattern_persisted` whenever it wrote the install-level fallback pattern into `adr-config.adrplus` -- on success, on any failure it reports, and when interrupted.
- Multi-write commands write the recoverable part first: `supersede` writes the successor (claiming its sequence number on disk) before marking the predecessor `Superseded`, and `reject` reverts a predecessor before writing its own `Rejected` status. A failure in between reports exactly what was already written (`supersede-write-failed` with `data.successor`, `reject-own-write-failed-after-predecessor-reverted` with `data.predecessor_file`).
- `adrpy-skills install`/`remove --allow-external-links` — explicit opt-in for a target reached through a junction or symlink (e.g. a dotfiles setup linking `.claude/skills`).
- Every failure response carries `detail` on stdout: a human-readable explanation, for people -- decide on `code`/`data` (see [ADR010](doc/adr/ADR010V01-failure-responses-carry-a-human-readable-detail-in-the-stdout-json,-with-stderr-kept-as-a-copy-outside-the-contract.md)). The same text is still written to stderr, as a copy outside the contract.
- Argument parsing is stricter for every `adrpy` and `adrpy-skills` command: a flag given twice is a `usage-error` instead of the last one silently winning, and one of the command's own flags in a value position (`-p --path x`) is reported as the missing value it is. A value that is exactly one of the command's own flags can't be passed as is -- for a path, write it as `./-p`.
- `adrpy-skills`: a failure partway through `install`/`remove` now reports what that call already did (`data.installed`/`removed`/`skipped` and the warnings collected) as `io-error` or `interrupted`; a file that is not valid UTF-8 is an `io-error` naming it.

### Security

- Closed 3 confirmed bypasses of the `folderadr`/`folderlog` containment guard's schema-time string comparison: a `../` traversal, a backslash-separated nesting on Windows, and a bare case difference, each resolving to the same or a nested real directory despite comparing unequal as raw strings — the comparison now normalizes to the host's own path components (`.`/`..` collapsed, case-folded) before comparing.
- Closed a real-filesystem junction/symlink aliasing bypass of the `folderadr`/`folderlog` containment guard: the schema-time check alone cannot see a junction or symlink planted inside the repository tree that makes two configured paths alias the identical real directory — `reject_aliased_repo_folders` now additionally resolves both fields for real and compares the resolved paths, wired into `init`, `config`, and `log`.
- Narrowed a check-then-use TOCTOU window in that same real-filesystem guard: each of its 3 call sites now re-verifies immediately before committing its write, not just before starting, closing the gap between the check passing and the write landing.
- `adrpy-skills install`/`remove` refuse to write or delete through a junction or symlink that leads outside the target (`--path`, or the home directory for `--target global`) with `path-outside-repository`, unless `--allow-external-links` is given; the core commands' orphaned-temp-file sweep no longer follows such a link out of the decisions folder.
- Orphaned-temp-file sweeps delete only this tool's own temp-file names (`<name>.<32-hex uuid4>.tmp`) next to the files a call writes — never another `*.tmp` of the user's.
- `adrpy-skills remove` never deletes a file the user wrote at a shared-doc path (`doc/ai-skills/<name>.md`) that no installed stub points at.
- `adrpy-skills` caps every file read at 10 MB instead of loading any file whole.
