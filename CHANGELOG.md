## [Unreleased]

The first release of adrpy-ai.

### Added

- **The ADR lifecycle as a CLI, flags in and JSON out.** `init`, `new`, `approve`, `reject`, `undo`, `supersede` (`--title` gives the successor its own title), `version` and `revise`, plus `migrate` for hand-written decision files, `explore` (an inventory of every file), `check`, `config`, `installconfig` and `log`. No command ever prompts. Every result is one JSON object on stdout; every failure has a stable code from one registry ([ADR005](doc/adr/ADR005V01-failure-codes-and-shared-constants-gain-dedicated,-closed-registry-classes.md)), listed with its condition in the command's `describe()` (`failure_codes`, [ADR008](doc/adr/ADR008V01-describe()-gains-a-structured-failure-codes-field,-sourced-from-shared-per-module-dictionaries-for-universally-reachable-codes.md)), and a human-readable `detail` for people ([ADR010](doc/adr/ADR010V01-failure-responses-carry-a-human-readable-detail-in-the-stdout-json,-with-stderr-kept-as-a-copy-outside-the-contract.md)). `adrpy help <command>` returns the full contract, and the pages under `doc/commands/` are generated from it.
- **Validate before acting.** Every lifecycle command (`new`, `approve`, `reject`, `undo`, `supersede`, `version`, `revise`) first validates the whole repository -- headers (git merge-conflict markers, a missing or damaged header, a status combination the tool never writes), numbering (no two files with the same number, version and revision), the family rules (one open `Proposed` and one `Superseded` at most, each the live member) and supersede links in both directions. If anything is broken it fails with `repository-inconsistent`, listing every problem with a repair hint in `data.errors`, and writes nothing. `config` does the same before changing a guarded field. A `.md` whose name is not an ADR name is ignored. See [`doc/lifecycle.md`](doc/lifecycle.md).
- **`adrpy check`.** The same validation, read-only: exit code `0` when the repository is consistent, `1` with every error listed otherwise -- for a pre-commit hook or CI (snippets in the README).
- **Family rules.** Only the latest member of a family is alive, unless every newer one is `Rejected`; a superseded family is frozen, and rejecting its successor is the one way back; a rejected successor's family is the end of its line. `revise` numbers after the highest revision its version already holds.
- **Single-owner model.** adrpy does no locking: one owner per git working copy, git coordinates people, and adrpy commands are not run in parallel on the same working copy. Every write is atomic (the complete content in a temp file, then an atomic move), and a file is never created over an existing one: a decision by `new`, `supersede`, `version` or `revise` (`file-already-exists`), a decision-log entry by `log` (`log-entry-already-exists`), the config of a fresh `init` (`config-already-exists`). `supersede` and `reject` of a successor prepare both files before writing either; if the second write fails, `multi-file-write-partially-applied` names what was written and gives the exact header row to put in by hand (`data.repair`).
- **Reads AdrPlus 1.0.0 repositories.** The same `adr-config.adrplus` and 12-line header, a status with no hidden canonical marker read from its label ([ADR004](doc/adr/ADR004V02-decision-status-recognition-uses-a-hidden-canonical-marker;-status-labels-and-the-filename-separator-both-gain-an-existing-decisions-guard.md)), and files AdrPlus migrated (`<!-- Migrated -->`). The few states AdrPlus 1.0.0 can leave that break a rule are reported with a hint, for a one-time repair by hand (see "Adopting adrpy on an AdrPlus 1.0.0 repository" in the README).
- **Configuration.** Status labels, the filename separator and `migrationpattern` can't be changed once doing so would break recognition of an existing decision (ADR004); `folderlog` places the decision log in its own, recursively scanned directory ([ADR007](doc/adr/ADR007V01-decision-log-directory-becomes-an-independent,-recursively-scanned-config-field-instead-of-a-fixed-sibling-of-folderadr--003.md)); a per-user install-level config seeds `init` and supplies `migrate`'s `migrationpattern` fallback ([ADR002](doc/adr/ADR002V01-install-level-config-is-a-per-user-file-that-seeds-init-and-migrate-instead-of-an-install-directory-template.md)); `--language` seeds the header and status labels from a bundled language pack.
- **`log`** writes a decision-log entry, the lighter-weight sibling of a formal ADR, and regenerates the log's index ([ADR003](doc/adr/ADR003V01-decision-log-entries-separate-human-reviewed-judgment-from-tool-executed-mechanics-via-a-future-adrpy-log-command.md)).
- **Tolerant reading.** A leading BOM is ignored and dropped on the next rewrite; a byte that is not valid UTF-8 outside the header is replaced on the next rewrite, with a warning; a file re-encoded as UTF-16/UTF-32 counts as a damaged header, never as a file with no header. Filenames, `migrationpattern` and integer flags accept only ASCII digits.
- **Strict arguments.** A flag given twice is a `usage-error`, and one of the command's own flags in a value position (`-p --path x`) is reported as the missing value it is.
- **`adrpy-skills`**, a separate console script in the same distribution, never called by `adrpy`: installs the `adrpy`, `decision-log` and `pre-release-audit` skills for Claude Code, Cursor, GitHub Copilot and a generic `AGENTS.md`, as a full body or a short stub plus one shared doc depending on the provider ([ADR009](doc/adr/ADR009V01-ai-coding-agent-skills-installer-ships-as-a-separate-adrpy-skills-entry-point-with-per-provider-full-body-or-stub-delivery.md), [`doc/skills/`](doc/skills/README.md)). Every file it writes carries a content-hash drift marker: a file or block that is foreign, hand-edited or malformed is left alone unless `--force` is given, and `list` reports the same state read-only.
- **The `adrpy` skill**, installed by `adrpy-skills install` alongside the others: it applies to ADR tasks in a repository that has `adr-config.adrplus`, and tells an agent to run `adrpy help` and `adrpy check --path .` first and follow each error's `hint`, to change decision files only through the commands (never renaming, hand-writing or hand-editing them, never removing a successor's `--NNN` suffix), to supersede with `adrpy supersede --file <predecessor> --title ...`, to repair by hand only as a hint says, and to run one command at a time. It also keeps the agent to what the user asked: no `approve`, `reject` or `undo` unless asked (creating or superseding a decision does not accept it), the decision's text written only with what the user gave (open sections are asked about in one question, never invented, and Deciders or dates never taken from git), a request to review whenever it wrote a decision's text, and `check` before the first change even after `explore`. Asked to fix a failing `check`, it applies the hint's first option and says so. `migrate` is a one-time adoption step: it previews a pattern first, and asks in one question before moving files that are not decisions (and does not ask when there are none). It also asks for a review after creating a decision, never approves a decision to make `version` or `revise` work, treats a described replacement as a supersede, reports migrated decisions as having no status, relays the warnings commands return, and keeps the placeholder of a line it only partly fills. `doc/skills/README.md` recommends a model at least as capable as Claude Sonnet 5 for tasks that write decisions; other providers were not tested with a real agent. It ends with a one-line map of every command. See [ADR011](doc/adr/ADR011V01-adrpy-skills-ships-an-adrpy-skill-that-makes-an-ai-agent-use-the-cli-instead-of-editing-adr-files-by-hand.md).
- **ADR names.** A decision's name starts with the configured `prefix` (compared case-insensitively) and carries a `V` version: `<prefix><number>V<version>[R<revision>]<sep><title>[<sep><sep><NNN>].md`. Any other `.md` -- `0001-use-postgres.md`, `2024-01-15-meeting.md` -- is ignored; a legacy name is recognized only through `migrationpattern`. A `--NNN` suffix makes a successor only when `NNN` is lower than the file's own number. See "ADR names" in [`doc/lifecycle.md`](doc/lifecycle.md).
- **`prefix` is a guarded config field**, like the separator: it can't be changed once a decision exists, or when the new value would adopt files that are not decisions today (`prefix-change-would-adopt-unrelated-files`).
- **A header row with an extra `|` is invalid** (`field-contains-forbidden-character` for the title, scope and domain); the extra cell is never silently dropped.
- **`new` and `supersede` refuse a number that does not fit `lenseq`** (`lenseq-too-small-for-new-number`), saying which `adrpy config --lenseq` widens it, or that it is already at its maximum.
- **A name too long for the filesystem is refused before writing** (`filename-too-long`): a title, or a decision-log scope and slug, whose file name plus the temp file's suffix would pass the limit of one name (255 bytes in UTF-8, the strictest of NTFS, ext4 and APFS); `version` and `revise`, which cannot change the title, say to supersede with a shorter one.
- **`interrupted` carries data once something was written**: `supersede` and `reject` after their first file (`data.applied`, `data.pending`, `data.repair`), `log` after the entry, before `INDEX.md` (`data.file`), `migrate` after a file (`data.results`); these four count a file as written from its bytes on disk, even when the interrupt arrives right after the rename that wrote it. The read-back that decides it retries a transient permission error, and a second Ctrl+C during it only leaves that one file unconfirmed; `migrate` reports what it had migrated on any unexpected error, never listing a file twice.
- **Orphaned temp files are swept everywhere this tool writes**: the decisions folder, the decision-log folder (by `log`), and the temps of `adr-config.adrplus` (by `init`, `config` and `migrate`) and of the install-level config (by `installconfig`).
- **Few partial writes**: `log` validates the decision-log folder before writing the entry; a refused `config` removes the folders it created; the temp-file sweeps skip anything that is not a regular file; a reservation that cannot be removed is an `io-error`, not a false `file-already-exists`; a folder `config` cannot finish creating leaves none of its new parents; `config --migrationpattern` computes its preview before writing.
- **`migrate` is a one-time adoption step.** It checks in a fixed order -- a damaged header, then a valid header it did not write, both before a `migrationpattern` is needed -- and every refusal about specific files names them in `data.files`. It always needs a `migrationpattern`, processes the files by name (the same order on every filesystem), skips a 0-byte file with a warning, and warns about a likely misread pattern (a title that starts with the separator, a number far above the others).
- **Once a repository is adopted, a legacy-scheme name without a header is not a decision** ([ADR012](doc/adr/ADR012V01-once-a-repository-is-adopted,-a-legacy-scheme-name-without-a-header-is-no-longer-a-decision.md)). While `migrate` can still run -- no decision has a valid header `migrate` did not write -- such a file is `no-header` and every command refuses until `migrate` finishes, a partial run's leftovers included. After that, a file whose name only matches `migrationpattern` (a note added later, say) is left out of every rule, count and listing, and `check`, `explore` and every lifecycle command warn about it, naming its number; after `new`, `version`, `revise` or `supersede` the warning says when the decision just written shares that number. A legacy name with a valid header stays a decision; a command given such a file as `--file` fails with `filename-not-recognized`.
- **`migrationpattern` safeguards.** A pattern that reads part of a name twice (a title starting inside the number's range, as `N00:04T02` for `0001-title.md`, or two ranges overlapping) is refused by `config`, `installconfig`, `init --seed` and `explore --migrationpattern` (`config-migrationpattern-invalid`, naming the overlap) and by `migrate` before writing; a config that already holds one still loads and can be corrected while no decision was migrated with it, and after that `migrate` finishes with it and warns. Changing or clearing `migrationpattern` is refused only while a legacy-scheme decision with a valid header exists. `explore --migrationpattern <pattern>` previews what a pattern reads from each name (`migrationpattern_preview`) and writes nothing; `config --migrationpattern` returns the same preview for what it wrote.
- **`undo` of a migrated decision returns `status: null`**: clearing its Changed cell makes it a migrated placeholder again, not `Proposed`.
- **Warnings without failing**: `check` and `explore` warn about a `.md` in the decisions folder whose name starts with a digit but is not an ADR name (most likely a decision written before adrpy), and about a file in the decision-log folder that is not an entry (`adrpy log` refuses to write while it is there).
- **Hints and messages say what to do.** The `successor-without-predecessor` and `superseded-not-live` hints quote the literal row to write, with this repository's labels, ordered by preference (and say not to rename the successor: its `--NNN` suffix is the link). A 0-byte file is named in the `no-header` detail; one with a legacy-scheme name is the user's file (the tool creates only current-scheme names), and the hint says to ask before removing it. `still-proposed` says which status each command needs, and that whether to accept or reject the decision is the user's. The adoption condition is named as the docs do: a file with a valid header `migrate` did not write. `config-not-found`, `cannot-determine-root-path`, `revision-not-configured`, an unknown command and an unknown argument each name the command that gets past them.
- **Exit codes**: 0 on success, 1 on a failure, 2 on a malformed call (`usage-error`, and `unknown-command` from both `adrpy <name>` and `adrpy help <name>`). `adrpy <command> --help` (and `-h`) is `adrpy help <command>`, the same in `adrpy-skills`; a missing required flag's `usage-error` shows an example (`adrpy check --path .`).
- **`init` writes `adr-config.adrplus` exactly as `config` does**, so a later `config` change rewrites only what it changes; an empty `adr-config.adrplus` fails with `config-file-empty`. `installconfig --seed` and `--language` warn which earlier values their replace of the whole file dropped.
- **The `decision-log` skill's write gate honors an explicit request.** When the user's own message explicitly asks to record a specific decision or entry, that request is the approval for that one write: the agent fills only what was given, asks only for missing required fields, and reports what was written. Approved writes go through the `adrpy` commands, never a hand-written file.
- **Python 3.11 to 3.14** are supported and tested in CI, on Linux, macOS and Windows.
- Public project scaffolding: `LICENSE` (MIT), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, this changelog.

### Security

- Every path the tool resolves must stay inside the repository, by real path resolution (following `..`, symlinks and junctions), never a string pattern. `folderadr` and `folderlog` must not be the same directory or nested in each other, compared both as normalized paths and as real paths, so a junction or symlink that aliases them is refused too.
- `adrpy-skills install`/`remove` refuse to write or delete through a junction or symlink that leads outside the target (`path-outside-repository`) unless `--allow-external-links` is given, and cap every file read at 10 MB. `remove` never deletes a file the user wrote at a shared-doc path that no installed stub points at.
- Orphaned-temp-file cleanup deletes only this tool's own temp-file names (`<name>.<16-hex>.tmp`, and the 32-hex form too; in the decisions and decision-log folders only a `.md`'s), never another `*.tmp` of the user's, and never follows a link out of the folder it cleans.
