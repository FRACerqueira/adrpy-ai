# folderadr's older guard shared the same 'unrecognized file silently adopted' gap separator had before round 20

**Front:** Stability audit (round 22, 4th pass, unfiltered) | **Severity:** Medium | **Resolution:** Direct | **Round:** 22

A round-22 stability pass, searching for siblings of the invariant round 20 closed for --separator, found reject_folderadr_change_if_decisions_exist (the older, pre-ADR004 guard governing --folderadr, established under ADR001) has the same shape gap: every check in it was keyed on the OLD folder, none caught the NEW folderadr already pointing at a directory with an unrelated pre-existing file that happens to match the naming scheme. Confirmed live: config --folderadr unrelated-docs succeeded silently on a directory containing one such file, then the next `new` call allocated ADR008V01 instead of ADR001V01, proving the pre-existing file was absorbed and corrupted numbering with zero warning. Fixed with a new adoption-check mirroring --separator's own (ADR004V02, round 20): after the existing OLD-folder checks pass, the NEW folder (if it already exists -- skipped entirely otherwise, since find_unreadable_subdirectories treats a missing path as unreadable) is scanned under the config that will govern it going forward; any file that would newly parse as a decision blocks the change with a new failure code, folderadr-change-would-adopt-unrelated-files. reject_folderadr_change_if_decisions_exist's signature gained two new keyword-only parameters (target, new_config) to resolve and scan the new folder; both call sites (config.py, init.py --seed) and the one existing direct test updated accordingly. Covered by new tests at all three layers (core/lifecycle.py, config, init --seed) plus a companion test proving a non-matching or not-yet-existing new folder still succeeds; mutation-confirmed (disabling the new check made all three rejection tests fail for the predicted reason).
