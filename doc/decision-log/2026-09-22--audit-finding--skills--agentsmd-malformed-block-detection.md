# AGENTS.md block parsing now detects and blocks a truncated or duplicated block instead of silently corrupting the file

**Front:** Round 33: hash-marker and stability fronts | **Severity:** Medium | **Resolution:** Direct | **Round:** 33

Two malformed shapes in AGENTS.md's marked-block format were unhandled: a start tag with no matching end tag (truncated -- reproduced install() silently appending a second, conflicting block, ending with 2 start tags and 1 end tag for the same skill, skipped:[], success:true), and more than one complete block for the same skill (duplicated -- reproduced install()/remove() only ever touching the first match via count=1, leaving a stale second copy permanently unreachable, even with --force). Fixed by adding _agentsmd_block_state(), layering malformed detection on top of the existing check_drift() state machine, used at all 4 call sites (install, remove, list, and the shared-doc-still-referenced check). 'malformed' is blocked exactly like 'foreign' via the same _blocks_write() guard used for the sibling finding in this round. A follow-on bug was found by this fix's own red/green test: forcing (--force) over a malformed state naively appended the fresh block after the old malformed fragment instead of cleaning it up first, leaving overlapping start/end tags that a later non-greedy parse could misread as spanning both the stale and the new block. Fixed in the same pass by adding _agentsmd_force_strip_all(), used before writing a fresh block whenever --force overrides a malformed status, on both the install and remove code paths. 4 new tests (TestAgentsmdMalformedBlocks) cover the truncated case, the duplicated case, and the force-cleanup path.
