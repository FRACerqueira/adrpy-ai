# revise numbering, a lenseq change, UTF-16 headers and non-ASCII digits no longer corrupt or crash

**Front:** Round 40: state-consistency front and pre-commit re-verification | **Severity:** Medium | **Resolution:** Direct | **Round:** 40

Fixed in 5b3b2a0, red/green for each. revise built the new revision from the header's Version and Revision cells, blank on a migrated placeholder, so it created V00 names and could repeat a revision number (F2); it now takes the version from the filename and numbers past every revision that version holds. reject compared the predecessor's back-reference as padded text, so a later config --lenseq (or init --seed) left the predecessor stranded as Superseded (F3); it now compares numbers. A tool header re-encoded as UTF-16 (PowerShell 5.1 Out-File, >) read as 'no header', so migrate wrote a blank header over it and silently erased an Accepted status; a NUL byte in the first 12 lines now marks a damaged header and migrate refuses (D3a). Non-ASCII digits (e.g. a superscript 2) in a filename, a Version/Revision cell or a back-reference passed isdigit() and crashed int() as internal-error; all seven checks now require ASCII digits (class closed: every isdigit() in src/ searched). revise of a file outside folderadr crashed on an empty max().
