# remove() and list_installed() now carry the same skipped/warnings contract shape install() already had

**Front:** Round 33: usability front | **Severity:** Low | **Resolution:** Direct | **Round:** 33

install() returned {installed, skipped (structured, with a reason), warnings}; remove() returned {removed, warnings (free-text strings covering the same concepts -- not-installed and drifted -- with no structured skipped list at all); list_installed() had no warnings key at all, breaking the project's own documented cross-command guarantee that every response, including read-only ones, always carries warnings even when empty (cli/explore.py, cli/help.py). Fixed: list_installed() now returns warnings: [] (always empty today, but closes the contract for any generic consumer); remove() gained a structured skipped list (same shape as install()'s: provider/skill/file/reason) for the drifted/foreign/malformed cases, keeping warnings only for the genuinely different not-installed no-op case; install()'s own previously-dead warnings field is now populated when --force overwrites something that was drifted/foreign/malformed, so that loss of a user customization is at least visible instead of silent. New/updated tests assert the new skipped shape on remove() and the warnings key's presence on list_installed().
