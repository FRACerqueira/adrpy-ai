# Empty/heading-less file crashed with a raw IndexError

**Front:** Stability audit | **Severity:** Medium | **Resolution:** Direct | **Round:** 14

Round 13 fixed _parse_entry's filename-shape split and classification-membership check to fail closed instead of crashing, but a .md file that passes both of those (a validly-shaped, recognized-classification name) with EMPTY or otherwise heading-less content still crashed one statement further down, at lines[0].lstrip('#').strip() -- the exact same bug class, just not given the same treatment. Confirmed empirically: a zero-byte file named 2026-01-01--audit-finding--lock--a.md raised a raw, uncaught IndexError from both max_existing_round (pre-write path, structured classifications) and regenerate_index (post-write path, every other classification) -- neither is a CommandError, so cli/log.py's except (OSError, LockLostError, CommandError) around the second write doesn't catch it either, meaning the post-write case silently loses the partial-success signal (the entry IS on disk, but the caller only sees a bare internal-error with no data.file). Fixed by checking for empty content in _parse_entry and failing closed with the same log-directory-contains-unrecognized-file code already used for the other two guards.
