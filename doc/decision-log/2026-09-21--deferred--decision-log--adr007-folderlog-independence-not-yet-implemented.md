# ADR007V01's independent, recursive folderlog field (superseding ADR003V01's schema driver) is accepted but not yet implemented

**Reopen-when:** before the next public release, when a repository layout actually needs folderadr and the decision-log directory in different locations, or when this becomes a blocker for other in-flight work

ADR007V01 (Accepted, supersedes ADR003V01's own driver 4 / Decision Outcome item 3) decided that folderadr and the decision-log directory become independently configurable (a new `folderlog` field in adr-config.adrplus, deliberately breaking byte-compatible round-tripping with the reference AdrPlus tool's own config schema), both recursively scanned, with a mutual containment guard (config-folderadr-folderlog-overlap) and a change guard mirroring folderadr's own folderadr-change-blocked-by-existing-decisions. The refactor itself (an estimated 8-10 files across core/config.py, core/decision_log.py, cli/config.py, cli/installconfig.py, cli/init.py, cli/log.py, default_repo_config.json and its language packs, plus doc/commands/*.md and tests) is explicitly NOT implemented yet, postponed the same way ADR005V01's registry refactor was.
