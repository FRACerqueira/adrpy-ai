# The original deferred item's own 6 named codes, plus ~35 more found in a first-pass scan, are now documented; a second, larger layer (26 more) is tracked via ADR005V01 instead

The original deferred item named 6 specific failure codes as counterexamples to doc/commands/INDEX.md's own absolute claim ('every failure code a command can return is documented inline'). All 6, plus a broader first-pass scan of every command's own directly-raised codes (init.py's config-already-exists/config-file-not-found, config.py's field-not-an-integer/field-not-a-boolean, core/lifecycle.py's target-directory-not-found/config-not-found/file-not-found/cannot-determine-root-path, every command's own ineligibility-reason dict codes like already-accepted/still-proposed/family-member-superseded, and several others -- roughly 35 codes across 12 commands total, including init.py's own lenseq/lenversion/lenrevision-too-small-for-existing-decisions) are now named explicitly in describe(). A second, broader script (every CommandError literal in every core/*.py module, cross-checked against ALL commands' combined describe() text) then found 26 MORE codes never named anywhere -- 22 of them core/config.py's own field-by-field validation grammar (config-prefix-invalid, config-lenseq-too-small, config-migrationpattern-invalid, and so on), plus filename-not-recognized, title-produces-unrecognizable-filename, path-invalid, and path-outside-repository. Given the recurring shape of this gap (found once by a narrow scan, then again at a larger scope by a broader one), the decision was made to close the remaining layer structurally rather than by hand a second time -- see ADR005V01 (failure codes and shared constants gain dedicated, closed registry classes) and the new deferred entry tracking that ADR's own not-yet-implemented refactor. This entry closes the ORIGINAL deferred item specifically -- its own named 6 codes, and the first-pass 35, are genuinely fixed now; the remaining 26 are deliberately NOT hand-patched, tracked instead via ADR005V01's own pending implementation.
