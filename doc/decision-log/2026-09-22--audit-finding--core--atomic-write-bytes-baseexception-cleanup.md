# atomic_write_bytes now cleans up its temp file on a non-OSError too, not just OSError

**Front:** Round 35: resilience front | **Severity:** Medium | **Resolution:** Direct | **Round:** 35

Round 35's resilience front (auditing adrpy-skills) found this live: patched os.replace to raise KeyboardInterrupt mid-write via installer.py's own atomic_write_text call, and the resulting .tmp file was left behind permanently -- in the target repo's own root, next to AGENTS.md, git-visible clutter -- because atomic_write_bytes only cleaned up on OSError. atomic_write_chunks already closed this exact class of gap for its own chunk-producer case (a LockLostError escaping mid-stream, found and fixed previously); that fix was never extended to atomic_write_bytes, the function every one of adrpy's and adrpy-skills' writers actually goes through via atomic_write_text. Not skills-specific -- a pre-existing gap in a module the whole project shares, just surfaced by the skills audit. Fixed by adding the identical except BaseException: temp_path.unlink(missing_ok=True); raise clause already used in atomic_write_chunks. New red/green test confirmed failing against the pre-fix code (temp file left behind) and passing after.
