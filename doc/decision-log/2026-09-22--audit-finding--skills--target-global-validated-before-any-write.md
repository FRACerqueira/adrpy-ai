# --target global is now validated for every requested provider before any write begins

**Front:** Round 33: filesystem-security, usability, and test-adequacy fronts | **Severity:** Medium | **Resolution:** Direct | **Round:** 33

install()/remove() validated scope=='global' support inside the per-provider loop, so a multi-provider call (e.g. the 'all' default) could already write or delete something for an earlier provider before a later one in iteration order (claude, cursor, copilot, agentsmd) triggered the usage-error -- reproduced: 'remove --target global' with no --provider deleted claude's real global file before raising on cursor. Fixed by adding _validate_scope(), called once against every requested provider before the per-provider loop starts in both install() and remove(), replacing the two inline per-iteration checks. Same root cause (a guard evaluated too late in the wrong place) also covered 2 related sub-issues in _expand(): --provider claude,claude was not deduplicated (dict.fromkeys(names) now preserves order while deduplicating), and an explicitly-empty value list after splitting on comma (e.g. --provider ",") silently fell back to 'all' instead of erroring, needlessly amplifying the blast radius of an accidental typo -- now a usage-error, distinct from omitting the flag entirely (which still means 'all'). New tests: TestGlobalScopeValidatedBeforeAnyWrite (2 tests asserting nothing was written/removed before the error), plus duplicate/empty-list cases in TestUnknownValues.
