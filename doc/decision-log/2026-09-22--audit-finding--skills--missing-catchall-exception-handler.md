# adrpy-skills' __main__.py now has a catch-all exception handler, closing a JSON-contract gap

**Front:** Round 33: usability front | **Severity:** Medium | **Resolution:** Direct | **Round:** 33

adrpy/__main__.py catches CommandError and has a final except Exception -> internal-error, with an explicit comment about never letting the JSON contract break; adrpy.skills.__main__.py only caught UsageError and OSError. Concrete gap: installer.py's several path.read_text(encoding='utf-8') calls (no errors=) would raise UnicodeDecodeError -- a ValueError subclass, not an OSError -- on a pre-existing non-UTF-8 file, uncaught, leaking a raw Python traceback to stderr with empty stdout, breaking the 'JSON in, JSON out' guarantee the project's own README advertises for the whole package including adrpy-skills. Fixed by adding the same except Exception as error: return emit_failure('internal-error', str(error)) as the last except clause, mirroring adrpy/__main__.py exactly (same noqa comment and rationale). A new test monkeypatches installer.install to raise a bare ValueError and asserts the CLI still returns a well-formed JSON envelope with code=='internal-error' instead of a raw traceback.
