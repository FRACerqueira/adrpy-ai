# AGENTS.md block ownership is proved by the marker hash, not by the indentation of its tags

**Front:** Round 39: narrow re-verification and pre-commit reviews | **Severity:** Medium | **Resolution:** Escalated | **Round:** 39

The tag-indentation rule had changed four times (C7, 720d3b8, R5a, P1b), each change creating a new edge, because the shape of a line cannot say who owns it. The owner chose layers of evidence (S1-a, S1-b ii), fixed in 02fe50f: tags at 0-3 spaces are the tool's syntax; with none, an indented pair whose de-indented content hashes clean is the tool's block (install updates it in place, remove deletes it only with --force, reason indented); any other indented copy is the user's text, never touched, and install appends a block with a warning. Also closed: a shared doc orphaned with or without --force, a duplication on --force, wrong warnings, 4+ BOMs, a block inside a list item, kept reported for a missing doc, and install --force over a malformed block adopting a user's indented copy. Accepted as out of scope: a verbatim indented copy left alone is adopted (byte for byte a re-indented block); a fence at column 0 is still the tool's; tags after > or - are not tags; a re-indented and edited block gets a new block; a canonical foreign block plus an indented copy; a forged marker; an edited copy citing the doc path keeps the doc; a copy inside another skill's block is adopted; blank lines with partial whitespace read as edited. Revisits 2026-09-22--risk-accepted--skills--drift-marker-not-tamper-evident: the marker now gives install rewrite leverage over an indented block, but what is written is always regenerated from the package's own resources. No ADR, by the owner's decision.
