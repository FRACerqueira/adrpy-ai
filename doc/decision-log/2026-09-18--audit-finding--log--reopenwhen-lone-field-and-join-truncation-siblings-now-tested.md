# reopenwhen-on-structured, lone-structured-field, and the join-truncation pattern's two remaining siblings are now tested

**Front:** Test-Adequacy audit | **Severity:** High | **Resolution:** Direct | **Round:** 15

Round 15's Test-Adequacy pass found three related test gaps in `run()`'s classification-dispatch validation, all confirmed via mutation against the current (unmodified, already-correct) production code:

1. **(High)** No test ever passed a lone structured field (`--front`/`--severity`/`--resolution`) together with a classification that is neither `audit-finding`/`doc-drift` nor `deferred`. The current `offending = provided_structured + ...` expression in the plain-classification branch already rejects this correctly, but mutating it to drop `provided_structured` let the suite pass with zero failures -- that mutant would silently write a corrupted structured line (literal Python `None` for the unset fields) to disk.
2. **(Medium)** The `STRUCTURED_CLASSIFICATIONS` branch's own `if provided_reopenwhen: raise ...` check was only ever exercised indirectly via a plain classification's rejection, never against `audit-finding`/`doc-drift` directly. Mutating it to `if False and provided_reopenwhen:` passed the full suite.
3. **(Medium)** The same '/--'.join(...) message-truncation pattern rounds 13/14 fixed once (round 14 decision-log: `2026-09-18--audit-finding--log--round-13-multi-flag-test-was-vacuous-missing-round-segment-untested.md`) had two more untested sibling instances in the same `run()` function: the 'missing structured fields' message (untested for the 'all three missing' case, the more likely real mistake) and the 'not valid on deferred' message (its only test passed a single flag and asserted exception type only, never message content). Each mutated join-truncation (`missing[0]`, `provided_structured[0]`) passed the full suite.

This is the same root cause rounds 12-14 each hit once and moved past without a sibling search: 'close the class, not the instance.' Fixed by adding four new tests (tests/test_log.py) -- `test_log_rejects_a_lone_structured_field_on_a_plain_classification`, `test_log_rejects_reopenwhen_on_audit_finding`, `test_log_names_all_three_structured_fields_when_none_are_provided`, `test_log_names_every_offending_structured_field_on_deferred` -- each verified red against its own mutation (for the reason predicted) and green after reverting; full suite (756 tests) green at the end.
