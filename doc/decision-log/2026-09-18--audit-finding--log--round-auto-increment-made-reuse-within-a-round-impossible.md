# Round auto-increment made reuse within a round impossible; --round is now an optional override

**Front:** Usability audit | **Severity:** High | **Resolution:** Escalated | **Round:** 12

adrpy log's first implementation always computed Round as max-existing-plus-one on every call, with no way to reuse a round. But doc/decision-log/INDEX.md's own header defines Round as identifying the pre-release-audit round an entry belongs to, and this project's own real data shows multiple entries sharing one round is the normal case (confirmed at the time: round 7 appeared 11 times, round 11 appeared 12 times). The auto-increment-always design made that impossible, and describe()'s own claim that automatic Round assignment meant it could never be reused by mistake was backwards -- reuse within a round is correct, not a mistake. Escalated because the fix carried a real design trade-off, presented as options and chosen by the project owner: --round is now an optional flag, valid only for audit-finding/doc-drift. Omitted, it auto-assigns the next round (the safe default for starting fresh) and the result's own warnings names the round it picked, since the tool has no session state and cannot know whether a given call is a continuation or a fresh start -- that context only exists on the caller's side. Passed explicitly, it reuses a round already in progress, validated to never regress below the current max (log-round-too-low) since Round is defined as never decreasing.
