# Multi-write recoverability sweep: log and migrate recover from a failed later write; supersede does not

Hypothesis, after reject's partial-failure bug (2026-09-22--retraction--cli--reject-write-order-reverted-predecessor-first.md): other commands with 2+ writes per call may leave an unrecoverable state when a later write fails. All 15 files in src/adrpy/cli/ were read and every multi-write command was reproduced with a monkeypatched failure on the later write. log (entry, then INDEX.md): recoverable -- regenerate_index rebuilds INDEX.md from every entry on disk, and the next log call re-indexes the orphaned entry. migrate (N independent per-candidate writes plus the config persist-back): recoverable -- a re-run migrates only the failed candidate, with no double header. approve/undo/version/revise/new/installconfig: single write per call, not in scope; init/config: mkdir then one write, documented as harmless. The hypothesis does not hold for log or migrate. It does hold for supersede, recorded separately once its fix is decided. Re-runnable: grep for atomic_write, mark_superseded and rewrite_status_field across src/adrpy/cli/.
