# retry_warning messages now identify which file; --force's malformed-block wording no longer claims the body was overwritten

**Front:** Round 36: re-verification front | **Severity:** Medium | **Resolution:** Direct | **Round:** 36

Same Round 36 re-verification pass, two Medium findings. retry_warning's own message (core/warnings.py) carries no file/provider/skill identity -- harmless for every other caller in the project (one write per command invocation, so there's never ambiguity), but installer.py's install()/remove() can write several files in one call, where an unqualified 'write succeeded only after N attempts' doesn't say which one. Fixed by prefixing provider/skill at all 4 retry_warning call sites, without touching the shared core/warnings.py function's own signature (used by 10+ other callers where the ambiguity never mattered). Separately: the --force warning for a malformed agentsmd block said the block was 'overwritten', but _agentsmd_force_strip_all only ever removes this skill's own tag lines, never a guessed span of orphaned body text between them (a deliberate, already-documented trade-off -- there's no safe way to determine a truncated block's true end boundary). That body text survives, unwrapped, immediately before the freshly written block -- the wording now says so explicitly ('tags replaced -- any orphaned body text... was left in place') instead of implying it's gone. Also cleaned up two dead-code items found during the same read: _other_stub_providers_reference's unused providers_in_target parameter, and _agentsmd_has_any_block (defined, never called anywhere in src/ or tests/). 2 new red/green tests for the two wording/identity fixes.
