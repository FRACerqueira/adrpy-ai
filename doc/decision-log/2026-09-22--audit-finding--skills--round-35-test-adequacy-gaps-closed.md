# 8 test-adequacy gaps closed: real-CLI alias/comma-split coverage, TOCTOU, malformed multi-skill, unicode, agentsmd shared-doc drift, performance scaling

**Front:** Round 35: test-adequacy front | **Severity:** Low | **Resolution:** Direct | **Round:** 35

Round 35's test-adequacy front (targeted at the tests written across rounds 33-34, not a general re-audit) found: -t/-f short CLI aliases were never exercised through the real CLI, only -p/-s were, despite two tests that looked like coverage (describe()'s own alias metadata, and an AST-based parse_flags cross-check) neither of which actually invokes the CLI with -t/-f -- a dropped alias in the real aliases={...} dict would have passed every existing test. The --provider ',' (empty-after-split) usage-error was only tested by calling installer.install([], ...) directly, bypassing commands/install.py's own _split() -- a regression there (e.g. silently falling back to 'all') would also have passed every existing test. -h (short --help) was never tested. The shared-doc unlink's own TOCTOU tolerance (a separate read-then-unlink sequence from the generic-provider branch, which already had a test) was untested. No test had two different skills both malformed in the same install()/remove() call. No test exercised non-ASCII content through the hash/marker round-trip or the AGENTS.md tag scan. Shared-doc drift/foreign protection was only ever tested via copilot; agentsmd is the other stub-mode provider, with its own more complex reference-counting via _other_stub_providers_reference, and had never triggered the scenario in any test. Separately: the AGENTS.md performance regression test's absolute 3.0s threshold (added in Round 34) was found to only reliably catch a full revert to the old catastrophic-backtracking regex -- a 'mild' quadratic reintroduction built from fast primitives (str.find/str.count in a loop) measured 0.14-0.78s at the same input size, comfortably under it despite being genuinely O(n^2). Closed with a scaling/ratio test (8x input size, asserting the time ratio stays well under quadratic growth) that catches the complexity class regardless of implementation constant factor. All 8 gaps closed with new tests; no production code change was needed for any of them.
