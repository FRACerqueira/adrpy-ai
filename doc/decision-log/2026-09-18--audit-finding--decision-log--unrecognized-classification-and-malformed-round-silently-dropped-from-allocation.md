# Unrecognized classification and malformed Round silently dropped from Round allocation

**Front:** Stability audit | **Severity:** High | **Resolution:** Direct | **Round:** 13

Round 12's fix gated _parse_entry's structured-line regex match by the entry's own classification (parsed from its filename), closing the false-positive risk of a non-structured entry's coincidental prose. Round 13 corroboration found this traded that false positive for a new false negative: an unrecognized or typo'd classification (e.g. 'audit-findings' instead of 'audit-finding') passes the filename-SHAPE check (still 4 '--'-delimited segments) but falls through the gating as neither structured nor deferred, silently discarding a real Round already on disk. Confirmed empirically: two files with Rounds 7 and 8 (the second misclassified), max_existing_round returned 7 instead of 8, and next_round then reissued Round 8 -- duplicating the round already in use on the misclassified file. A narrower, related gap: a correctly-classified structured entry with a malformed Round value (e.g. '5 (tentative)') was still silently treated as carrying no Round at all via the pre-existing except ValueError: continue guard -- same duplicate-Round risk, different trigger, and it was pinned as expected behavior by a passing test rather than flagged as an open risk. Fixed both with the same fail-closed philosophy already applied to a malformed filename shape: _parse_entry now validates the classification itself against the closed vocabulary and raises log-directory-contains-unrecognized-file if it isn't recognized; max_existing_round now raises the same code for a structured-classification entry whose Round is missing or not a plain integer, instead of silently skipping it. Both confirmed closed via live reproduction of the original repro steps.
