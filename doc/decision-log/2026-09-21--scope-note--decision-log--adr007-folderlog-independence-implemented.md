# ADR007V01's independent, recursive folderlog field implemented, closing its deferred-implementation tracking entry

ADR007V01 (supersedes ADR003V01's schema driver) is implemented. `folderlog` is now an independently configurable, recursively-scanned config field, decoupled from `folderadr` (no longer a fixed, non-recursive sibling). Verified independently, not just by the implementer: backward-compat confirmed (an existing config with no folderlog key still parses, defaulting to the exact old computed sibling value, with a safe fallback to '' rather than a crash if folderadr itself has the wrong type); the mutual containment guard (config-folderadr-folderlog-overlap) compares by path COMPONENT via PurePosixPath.parts, confirmed correct by reading the code directly -- 'doc/adr' vs 'doc/adr2' does not false-match, equal/nested-either-direction all correctly rejected; the change guard (folderlog-change-blocked-by-existing-entries / folderlog-change-would-adopt-unrelated-files) mirrors folderadr's own existing shape; the decision-log directory's own scan is now recursive (rglob, matching folderadr's own convention) and fails closed on an unreadable subdirectory (log-scan-incomplete) instead of silently under-reporting. Per an explicit mid-task request, the length/relative-path validation shared between folderadr and folderlog was consolidated into one _validate_relative_repo_path_field helper instead of two hand-written copies, mirroring this session's own 'close the class, not the instance' discipline. core/config.py's own module docstring, which stated outright 'no field is ever added to it', is corrected. One real behavior difference found and deliberately kept, not silently smoothed over: the decision-log directory's own scan is STRICTER than folderadr's -- it fails loudly (log-directory-contains-unrecognized-file) on any unrecognized .md file rather than silently ignoring it the way folderadr's scan_decisions does, since decision-log entries have always had this fail-closed convention (pre-dating this ADR) and ADR007V01 never proposed relaxing it.
