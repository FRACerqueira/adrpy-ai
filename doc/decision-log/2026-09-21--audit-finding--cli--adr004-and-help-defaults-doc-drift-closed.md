# Four doc-vs-code drifts found around ADR004 and help's summarized defaults, all closed

**Front:** Usability audit | **Severity:** Medium | **Resolution:** Direct | **Round:** 19

An independent usability pass comparing describe()/doc pages against actual code, scoped to this session's config/init/installconfig/help changes, found four drifts. (1) help.py's own describe() (and its README/doc/commands/help.md echoes) claimed 'defaults' in the summarized bare adrpy help listing was 'the config fields a fresh init would produce', when _DEFAULTS_PREVIEW_FIELDS actually exposes only 11 of RepoConfig's 27 fields, with no qualifying language anywhere user-facing. (2) doc/commands/INDEX.md's installconfig row was missing the parenthetical ('seeds new repositories, supplies a migrate fallback') its own live describe()['summary'] and README already carry -- confirmed as the only drifted row via a full sweep of every command's live summary against INDEX.md, not just the one instance found. (3) --separator's PERMANENT/no-migration-path consequence was documented only on config's own describe(), never on init --seed's -- a second real path to the same irreversible change. (4) doc/commands/help.md rendered the positional command argument with the same header style as a real flag, right next to this session's own new --full flag, implying 'adrpy help --command X' works when only 'adrpy help X' does. All four fixed directly: help.py's description now explicitly names the omitted field categories and points at installconfig/config for the full set; INDEX.md synced; init.py's --seed description (and doc/commands/init.md) now states the guard's scheme-scoped/permanent consequences explicitly; help.md's positional-argument heading no longer reads like a flag.
