# ADR005V01's centralized FailureCodes/Defaults registry is accepted but not yet implemented

**Reopen-when:** the security-audit rounds currently in progress conclude, a third documentation-completeness gap of this same shape is found, or before the next public release, whichever comes first

ADR005V01 (Accepted) decided that failure codes and shared constants/defaults should move into a single, central `FailureCodes` class (core/errors.py) and an equivalent centralized `Defaults`/`Constants` treatment, replacing today's scattered module-level literals and dicts (including the already-confirmed `_INT_FIELD_BOUNDS` duplication between config.py and installconfig.py). The refactor itself -- an estimated 15-20 files across src/adrpy/core/ and src/adrpy/cli/ -- is explicitly NOT implemented yet, postponed so the in-progress security-audit rounds (27+) could close out first. Once implemented, it also closes the remaining ~26 undocumented failure codes found during this same session (22 of them core/config.py's own field-by-field validation grammar) -- these are deliberately left undocumented-in-place rather than hand-patched now, specifically to avoid documenting them once against today's scattered constants and then again against the new registry once it lands.
