# A 4th containment-guard bypass (junction/symlink aliasing, invisible to the schema-time check by construction) found and closed with a second, real-filesystem-resolution layer

**Front:** Security audit (round 30, 9th pass -- pre-release audit, focused single-angle re-verification of round 29's own containment-guard fix) | **Severity:** High | **Resolution:** Escalated | **Round:** 30

Round 30's single, focused Security verification of round 29's own containment-guard fix (commit 8453604) confirmed the fix solid for the class it targeted (string-based '..'/case/backslash bypasses -- re-verified live with additional variations, all correctly rejected), but found a genuine 4th, structurally different bypass: the schema-time guard (core/config.py's parse_repo_config) only ever sees config TEXT, never the filesystem -- it cannot see a Windows junction or symlink planted inside the repository tree that makes folderadr/folderlog strings sharing NO path-component prefix at all (e.g. 'doc/adr' and 'doc/other') alias the identical real directory. Confirmed live, independently, by both the audit pass and the coordinator directly: a real junction (doc/other -> doc/adr) makes Path.resolve()/.samefile() agree the two are the same physical directory, while parse_repo_config accepts the pair silently. End-to-end reproduction via the real CLI confirmed the exact corruption class round 29's own commit message used as its own proof (log-index-regeneration-failed, an ADR file misrecognized as a decision-log entry) -- 'init' + 'new' + 'log' collided on one physical directory. Fixed with a second, real-filesystem-resolution layer: core/security.py's new reject_aliased_repo_folders(target, config) resolves both folderadr and folderlog via the already-proven resolve_within and compares the RESOLVED paths (equal, or either nested in the other, in either direction) -- new FailureCodes.FOLDERADR_FOLDERLOG_ALIAS_SAME_DIRECTORY. Wired into the 3 places folderadr and folderlog are both about to be used for real: cli/init.py (folder creation, the first point either folder's real location is knowable), cli/config.py (the --folderadr/--folderlog change path), cli/log.py (the only command that reads folderlog for its own normal work). Confirmed no other call site independently re-implements its own overlap logic that could carry the same gap (all other config.folderadr/folderlog readers only do string-equality change-detection or single-field resolve_within containment, never a mutual check). Mutation-verified: disabled the new check's own condition, confirmed the new regression test failed for the predicted reason (DID NOT RAISE), restored, confirmed green. End-to-end re-verified live via the real CLI (not just the unit test): the exact init+junction scenario that previously succeeded silently now correctly fails with folderadr-folderlog-alias-same-directory. ADR007V01 revised (undo -> edit -> approve): its own Decision Outcome claimed the schema-time guard 'runs at config-parse time... closes the hazard' -- corrected to 'necessary, not sufficient', documenting the second, real-filesystem-resolution layer this finding required. 2 new tests in test_security.py (the Windows-junction case, skipif-guarded matching the project's existing junction/symlink test-split convention, plus the required adversarial positive control: 2 genuinely separate directories must not trip the check). Suite: 1022 passed, 3 skipped, 1 xfailed, 0 failed.
