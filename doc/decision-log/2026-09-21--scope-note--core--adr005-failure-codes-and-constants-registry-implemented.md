# ADR005V01's FailureCodes (130 codes) and Constants registry implemented, closing its deferred-implementation tracking entry

ADR005V01's FailureCodes/Constants registry is implemented. core/errors.py gained a FailureCodes class with all 130 confirmed failure codes as attributes (89 core, 41 cli), migrated one file per batch (21 files) with the full suite green after every single one -- verified independently, not just by the implementer: every FailureCodes attribute's name mechanically matches SNAKE_CASE(its own value) (0 mismatches), and a repo-wide grep confirms zero orphaned raw string literals duplicate a registry code. Per-command _INELIGIBILITY_DETAILS dicts (6 files) kept their human-readable VALUES local, only their KEYS moved to FailureCodes, resolving the one question ADR005V01 itself left open. A new permanent test (test_every_failure_code_is_documented_somewhere) makes 'every code is documented' mechanically checkable -- confirmed genuinely red when forced (--runxfail): 59 of 130 codes, almost entirely core/config.py's own field-validation grammar and core/header.py's granular parse codes, are still undocumented in any describe() text. Marked xfail(strict=True) rather than silently accepted, since closing that gap is a separate, large documentation sweep already named as deliberately-not-hand-patched-again in this session's own earlier decision-log entry -- the xfail will start failing loudly the moment that gap closes, so it can't go stale. doc/commands/INDEX.md's own 'every failure code is documented' claim was corrected to point at this tracked, checkable gap instead of asserting completeness. Of the Constants class's own 5 flagged duplications, 4 were consolidated (_INT_FIELD_BOUNDS into core/config.py; the 65536 stream-chunk-size constants in core/lifecycle.py and cli/migrate.py into a single core/atomic_write.STREAM_CHUNK_SIZE; the 4-field status-label tuple in core/lifecycle.py sourced from core/config.py's own _STATUS_LABEL_FIELDS instead of a second literal copy; the case-transform name set in core/config.py sourced from core/casing.py's own dispatch dict instead of an independently-typed tuple) -- the 5th (LOCK_IO_RETRY_* vs IO_RETRY_*) was left as two separate constants on purpose, per an existing, explicit design comment in core/lock.py stating the separation itself is deliberate (so a future tuning change to one site can't silently drift the other), not an oversight ADR005V01's own rationale would apply to. Suite: 1012 passed, 3 skipped, 1 xfailed, 0 failed. This is implementation of an already-Accepted, already-deferred ADR, not a fresh audit finding -- logged as scope-note, not audit-finding, so it does not retroactively alter the already-closed 17-28 cycle's own calibration numbers.

Architectural review (Round 43): the per-command `_INELIGIBILITY_DETAILS` values are no longer local: they became one shared text per code in `core/lifecycle.SHARED_FAILURE_CODES`. The `LOCK_IO_RETRY_*` constants went with `core/lock.py` (ADR001), and the lock codes, the resume codes and three lifecycle scan-incomplete codes (family-, new- and supersede-successor-scan-incomplete, now one scan-incomplete validator error) left the registry.
