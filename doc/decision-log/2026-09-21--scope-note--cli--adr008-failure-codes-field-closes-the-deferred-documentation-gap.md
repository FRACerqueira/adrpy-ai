# ADR008V01 implemented: closes the deferred every-failure-code-documented claim

Closes the item deferred in 2026-09-21--deferred--cli--index-md-every-failure-code-documented-claim-is-false.md. Every command now exposes a structured failure_codes field on its own describe() response (ADR008V01) -- a list of {code, condition} entries covering all 137 FailureCodes registry values, not just the previously-undocumented 62. Codes reachable identically from many-or-all commands (core/config.py's schema-validation grammar, 41 codes; core/header.py's header-parsing grammar, 17 codes; core/lock.py's REPOSITORY_LOCKED/LOCK_LOST; core/lifecycle.py's own 14-code set shared by the 6 per-file lifecycle commands) are authored once, in a SHARED_FAILURE_CODES dict living next to the code that raises them, and merged into every command's own failure_codes via a new build_failure_codes helper (core/errors.py) -- still delivered inside that command's own describe() response, never referenced from outside it, so doc/commands/INDEX.md's own no-global-index position for genuinely context-specific codes is narrowed, not reversed.

tests/test_help.py::test_every_failure_code_is_documented_somewhere no longer xfails -- it now checks the structured field directly (real structured-data completeness, not prose substring-matching), passing for real. 3 new tests close the adjacent gaps a purely-additive field could otherwise hide silently: every failure_codes entry is a real FailureCodes value (catches a typo/stale string), no command lists the same code twice (catches an accidental double-merge), and every entry has non-empty condition text.

The per-command/per-shared-dict mapping (which of the 137 codes belongs to which command) was derived via static analysis of the actual call graph (not hand-guessed), cross-checked against a full-registry-coverage assertion (all 137 codes must appear in the union of all 14 commands' own fields) before any description text was written -- and corrected twice after the mechanical pass produced false positives (a try/except-wrapped code misattributed to callers that never see the unwrapped version; a keyword-argument-dependent code path, config-not-found via init's own require_config=False, misattributed to init even though it structurally cannot reach it). Given the sheer number of hand-written one-line conditions (137) and the real risk of a code-to-condition mismatch in that transcription, the repo owner has already approved a dedicated verification round after this implementation, checking a sample against real raise-site behavior.

doc/commands/*.md (all 14 pages, hand-maintained, mirroring describe()) gained a new Failure codes table each, generated from the live describe() output rather than hand-typed, to avoid a second manual-transcription risk on top of the first. doc/commands/INDEX.md's own claim updated to describe the table-based, partially-shared-source model instead of the fully-inline-prose one it originally described.
