# supersede gains an optional --title flag, closing half of the deferred supersede-title-flag-and-adr007-retitle entry

Adds an optional --title flag to adrpy supersede, mirroring new --title's own validation exactly (reject_embedded_delimiter, reject_filesystem_unsafe_title, reject_title_with_no_case_transform_content, same order). When given, overrides the successor's title instead of the predecessor's own filename-segment title (today's default, unchanged when the flag is omitted -- confirmed byte-identical via a dedicated regression test). This is the followup this session's own 2026-09-21--deferred--cli--supersede-title-flag-and-adr007-retitle.md entry named: supersede previously had no way to give a successor a different title than its predecessor's own, which is why ADR007V01 itself was stuck carrying ADR003V01's own title. Real finding during testing: --title's own value is stored RAW in the header cell (not case-transformed), matching new --title's own already-established convention (confirmed against test_new.py) -- the no-flag default path differs only because filename_info.title already comes pre-transformed, having been extracted from an existing filename, not because of a different convention to replicate. Suite: 1034 passed, 3 skipped, 1 xfailed, 0 failed. This closes half of the linked deferred entry; the other half (retitling ADR007V01 itself) follows as a separate, manual step.
