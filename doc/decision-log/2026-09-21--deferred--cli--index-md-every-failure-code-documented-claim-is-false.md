# doc/commands/INDEX.md's absolute claim about failure-code documentation is checkably false

**Reopen-when:** the next documentation-only pass (per this project's own periodic doc-review cadence), or a dedicated audit round scoped to command describe()/doc-page completeness project-wide, whichever comes first

A round-21 comprehensive usability pass on the ADR004 area, while cross-checking the guard's own new failure codes against config.py/init.py's describe(), also checked doc/commands/INDEX.md's own footer claim ('Every failure code a command can return is documented inline... there is no separate global error-code index') against the real code, and found it false for several codes that predate ADR004 entirely and are unrelated to it: init.py's lenseq/lenversion/lenrevision-too-small-for-existing-decisions (reachable, never named in init.describe()/init.md despite the description explicitly setting up the reader to expect them), config-file-not-found and config-already-exists (never stated positively, only implied negatively), config.py's field-not-an-integer/field-not-a-boolean, and core/lifecycle.py's resolve_target_and_config raising target-directory-not-found/config-not-found for both commands. This is broader than ADR004's own scope (fixing it means auditing every command's full failure-code surface, not just the guard this session touched), so it is deferred rather than folded into this session's ADR004 fixes.
