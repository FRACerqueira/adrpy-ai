# Round-13 mutation testing found untested boundaries: round regression, INDEX.md LF-only success path, multiple offending flags

**Front:** Test-Adequacy audit | **Severity:** Medium | **Resolution:** Direct | **Round:** 13

Three independent zero-coverage boundaries, each confirmed by mutating the production code and re-running the suite unmodified. First: validate_round_not_regressing's every existing rejects-lower test used a gap of 2 (current_max=5, attempted=3) -- the adjacent value (attempted=4, exactly one below) was never exercised; an off-by-one in the comparison would have shipped silently. Second: regenerate_index's LF-only guarantee (real and load-bearing -- the committed doc/decision-log/INDEX.md is genuinely LF-only on disk) was only tested on the FAILURE path (the existing atomic-write test only proves a pre-existing file survives untouched when the write fails); reverting atomic_write_bytes back to atomic_write_text, which normalizes to the host's own line separator, passed every test in the suite. Third: cli/log.py's offending-flags list (multiple wrong/extra flags for a given classification, e.g. --round and --reopenwhen passed together on scope-note) already joins every offending flag name correctly in its UsageError message, but no test ever passed more than one at once -- collapsing the message to only the first offending flag also passed every test. Fixed by adding a dedicated test for each boundary: the adjacent-lower-round rejection, an LF-byte assertion on a normal successful regenerate_index call, and a two-simultaneous-offending-flags call asserting both names appear in the error message.
