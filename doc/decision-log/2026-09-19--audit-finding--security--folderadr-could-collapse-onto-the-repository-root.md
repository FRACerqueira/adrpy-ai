# folderadr could collapse onto the repository root itself via '.', whitespace-only, or a self-cancelling path

**Front:** Stability audit (confirmed exploitable, escalated from a Test-Adequacy-noted coverage gap) | **Severity:** High | **Resolution:** Direct | **Round:** 16

Round 16's Stability pass found that `folderadr` can be set to a value that resolves to the repository root itself, not a subdirectory of it -- confirmed live end to end.

Two independent, compounding gaps: `core/config.py` checks `folderadr` for non-empty, max length, and "not anchored outside the repo", but never for "does it actually name a strict descendant"; `resolve_within` (`core/security.py`) treated `resolved == base` as "inside", not rejected. On Windows, `Path.resolve()` silently strips a whitespace-only path component (and `.`/`x/..` cancel out to nothing), so `config --folderadr "."` or `"   "` both resolve to exactly the repository root. Every subsequent write then lands next to `adr-config.adrplus` itself, and `folder.rglob("*.md")` (scan_decisions/next_number/family-membership) scans the entire repository, not a contained subfolder.

The more dangerous entry point is `installconfig --folderadr`, not `config`: it does not validate against a repository at all (there isn't one yet), so a poisoned install-level config makes every subsequent `init` on that machine (no --seed given) silently create a repository whose decisions folder equals its own root -- confirmed live end to end (installconfig -> init -> new all succeed, with `new`'s ADR landing directly in the repo root). The existing-decisions guard (`reject_folderadr_change_if_decisions_exist`) never engages either way, since a fresh repository has zero decisions to protect.

Fixed at the shared root: `resolve_within` now also rejects `resolved == base`. Verified this is safe project-wide, not just for folderadr -- enumerated all 23 call sites (`config.folderadr` at 12 sites, a real filename at 11) and confirmed none legitimately expects the candidate to resolve to base itself. This closes the collapse for every entry point (`config`, `init` --seed, install-level config) in one place, no call-site changes needed. Verified red (all 6 new tests failed with 'DID NOT RAISE', the exact predicted outcome) against a mutation dropping the new `resolved == base` check, then green after reverting; full suite (798 tests) green.
