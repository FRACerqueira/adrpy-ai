# adrpy log now exists, closing ADR003V01's deferred implementation

Closes the deferred implementation named in ADR003V01 (doc/adr/ADR003V01-decision-log-entries-separate-human-reviewed-judgment-from-tool-executed-mechanics-via-a-future-adrpy-log-command.md): adrpy log is now a real command, not just an accepted design. It owns the mechanical part of a decision-log entry -- filename construction, the classification-specific structured line, writing, and INDEX.md regeneration, all inside the same repository lock every other write command already uses -- while classification, scope, slug, and content remain required, explicit arguments; judgment never moved into the tool. Round is computed automatically (highest existing Round across audit-finding/doc-drift entries, plus one) rather than typed, closing a class of error a human-supplied value could not avoid. A same-date/classification/scope/slug collision fails closed (log-entry-already-exists) instead of silently overwriting. core/decision_log.py's regenerate_index also replaces scripts/generate_decision_log_index.py's own duplicated logic, verified byte-identical output before and after the extraction. This entry is itself the first real-world use of the new command. A Stability/Test-Adequacy/Usability audit of this implementation is confirmed and pending before it is considered fully settled.
