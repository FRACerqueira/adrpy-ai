# Closed the deferred finding: separator can no longer silently adopt an unrelated file

**Front:** Stability audit (narrow verification pass, post-round-20) | **Severity:** Medium | **Resolution:** Direct | **Round:** 20

Closes the item deferred in 2026-09-21--deferred--header--separator-change-can-silently-adopt-an-unrelated-unrecognized-file.md. The existing-decisions guard (core/lifecycle.py's reject_status_or_separator_change_if_decisions_exist) now also checks, for --separator specifically, whether the change would make a file NOT currently recognized as a decision (by either naming scheme) newly parse as one -- reusing the already-scanned old-config recognized set and one additional scan under the new config, blocking with a new, distinct failure code (separator-change-would-adopt-unrelated-files, data.adopted_files naming the actual paths) rather than folding it into the existing blocked-by-existing-decisions code, since the two failures mean categorically different things (losing recognition of a real decision vs. gaining unwanted recognition of a non-decision) and data.existing_decisions would have been misleading either way for the adoption case. Deliberately NOT applied to migrationpattern -- newly recognizing pre-existing legacy files via that field is its own documented, intentional purpose (ADR002V01), not the defect this check exists to close. Closed with new tests in tests/test_config_command.py and tests/test_init.py (one per call site, mutation-verified) and folded into doc/adr/ADR004V02-... as a third correction, incorporated in place (never pushed) rather than a new ADR version, consistent with this session's own precedent.
