# An unrecognized filename in the decision-log directory crashed with a raw ValueError

**Front:** Stability audit + Test-Adequacy audit (independently, 2 fronts) | **Severity:** Medium | **Resolution:** Direct | **Round:** 12

_parse_entry's date, classification, scope, _slug = path.stem.split('--', 3) assumed every .md file in the decision-log directory (besides the two named exceptions, INDEX.md and CYCLES.md) matches the expected 4-part shape. A stray file that doesn't crashed with an uncaught ValueError, reaching __main__.py's generic exception handler and surfacing only as a bare internal-error, not a named, actionable failure. Confirmed empirically for both callers of the shared _existing_entries helper (next_round and regenerate_index). Fixed by catching the split's ValueError in _parse_entry and re-raising as a structured CommandError (log-directory-contains-unrecognized-file, data.file naming the offending filename). This surfaces differently depending on --classification, which is a real asymmetry, not an inconsistency to paper over: for audit-finding/doc-drift, the directory is scanned for Round allocation before any write, so it fails cleanly with nothing written; for every other classification, the directory is only scanned during index regeneration, after the entry write already committed, so it surfaces as log-index-regeneration-failed instead (the entry's own data.file names what was already written; the offending stray file's name is in the detail text).
