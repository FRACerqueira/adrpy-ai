# Round-19 guard tests never combined mixed-scheme repos with multi-field changes

**Front:** Test-Adequacy audit | **Severity:** Medium | **Resolution:** Direct | **Round:** 20

A round-20 test-adequacy pass on round 19's own new tests (the ADR004V02 scheme-scoped guard tests) found two gaps, both mutation-confirmed. (1) No test exercised a repository with BOTH a current-scheme and a legacy-scheme decision present while changing two guarded fields (one blanket, one scoped) in the same call -- mutating the guard's two independent field-group checks into an if/elif chain (so the second check is skipped once the first already matched) left the full suite green. (2) test_config_reports_the_correct_count_with_more_than_one_existing_decision's own fixture was scheme-homogeneous (3 current-scheme decisions, 0 legacy), so it could not distinguish a real total count from a real count correctly scoped by scheme -- mutating the count to only include current-scheme decisions left that specific test green (only caught incidentally by two unrelated tests elsewhere). Both closed with new mixed-scheme tests in tests/test_config_command.py, mutation-verified. These same tests also cover the guard's post-round-20 corrected design (see doc/adr/ADR004V02-...): migrationpattern is scoped to legacy-scheme decisions, separator and status labels are blanket.
