# A header a markdown formatter rewrote read as no header, so an Accepted decision dropped out

**Front:** Compatibility of existing repositories (round 51 confirmation, escalated) | **Severity:** Medium | **Resolution:** Escalated | **Round:** 51

prettier and mdformat insert a blank line after the header's comment and pad every cell; the header no longer parses, and has_header_shape read it as no header: check left the decision out of every rule and migrate would stack a second header on it. The owner chose to recognize it as a damaged header. Two intermediate versions did not hold (a second opinion reproduced each): a positional rule missed double faults and the real formatter shape, and a rule counting row labels missed headers whose labels `config` renamed after they were written (the labels are not guarded). has_header_shape now looks, in the first 12 lines, only for marks this tool writes and no config renames: the `(1-12) -->` comment on any line (the header also closes with it), a table row holding a status cell's canonical marker (ADR0004V01, any case) or ending in a comment as the migrated fields row does, the exact fields row, an exact `|--|--|` first line, a NUL byte. A differential against the previous code (361 fault cases, same and relabeled config, 519 real .md files in both repositories) shows no case it caught that the new code misses. Left, Low: a header with no status marker (hand-copied, or migrated with its Migrated comment gone) that lost both comment lines and whose fields row is no longer exact reads as no header -- what is left is a table on line 1 with a separator under it, which a note opening with its own table also has.
