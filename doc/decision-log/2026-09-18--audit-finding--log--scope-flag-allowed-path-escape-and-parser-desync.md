# --scope allowed path escape and delimiter desync; now validated as kebab-case

**Front:** Usability audit | **Severity:** High | **Resolution:** Direct | **Round:** 12

adrpy log's first implementation constructed the entry's filename from --scope with only reject_embedded_delimiter applied ('|' and line breaks) -- no resolve_within, and no restriction on '/', '\', or an embedded '--', unlike every other command that constructs a decision filename. Reproduced live: --scope '../../escaped' caused a raw internal-error and wrote the file to an unintended location, since scope is joined directly into a Path via string interpolation, and pathlib treats an embedded '/' or '\' as a real separator. An embedded '--' would also desynchronize _parse_entry's own split('--', 3), corrupting the scope/slug columns the next time the index is regenerated, silently. Fixed by adding validate_scope (core/decision_log.py), the same kebab-case check as slug, rejecting anything containing '/', '\', or a double-hyphen with a new log-scope-invalid code -- consistent with this project's own real scope values (lock, config, install-config, ...), which were already kebab-case in practice, so this only enforces what was already the convention.
