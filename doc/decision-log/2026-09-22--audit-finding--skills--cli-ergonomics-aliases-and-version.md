# adrpy-skills commands gained short flag aliases, --version/-v, and a value-listing usage-error, matching adrpy's own conventions

**Front:** Round 33: usability front | **Severity:** Low | **Resolution:** Direct | **Round:** 33

Every adrpy command passes aliases= to parse_flags and documents each alias via describe()'s own 'alias' field (see cli/init.py, cli/new.py, etc., and the cross-check test_short_flag_aliases_are_documented_in_describe in tests/test_help.py); no adrpy-skills command did either, despite parse_flags already supporting aliases= natively. adrpy also treats --version/-v as the one deliberate exception to JSON-only output; adrpy-skills had no equivalent, so 'adrpy-skills --version' returned a confusing unknown-command usage-error instead. Separately, _expand()'s 'Unknown value(s): ...' usage-error omitted the valid options, unlike core/config.py's own enum-validation errors, which always list them. Fixed: install/remove/list gained -p/-t/-s/-f aliases (documented in describe() via the same 'alias' field, and in doc/skills/*.md, matching doc/commands/*.md's own convention); adrpy-skills __main__.py gained a _print_version() mirroring adrpy's own; _expand()'s error message now appends 'Valid values: ...'. New tests: test_short_flag_aliases_are_documented_in_describe (mirroring the adrpy-side test), a --version/-v CLI test, and an 'Unknown value(s)' message-content assertion.
