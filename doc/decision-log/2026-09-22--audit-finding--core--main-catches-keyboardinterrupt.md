# adrpy/__main__.py now catches KeyboardInterrupt, closing the JSON-contract gap at the CLI boundary

**Front:** Round 36: core resilience front | **Severity:** Medium | **Resolution:** Direct | **Round:** 36

Round 36's core resilience front found KeyboardInterrupt is a BaseException, not an Exception -- the existing except Exception catch-all in adrpy/__main__.py's main() never sees it, so before this fix a Ctrl+C mid-command propagated raw, with empty stdout, exactly the failure mode this project's own JSON-contract guarantee exists to prevent. Confirmed live and dramatically: even pytest's own test run was aborted by the uncaught exception when reproducing it. Notable because the write layer (core/atomic_write.py) was already specifically hardened against this exact exception type in an earlier Round 35 fix (atomic_write_bytes cleans up its own temp file on any BaseException, not just OSError) -- the write layer treated it as a first-class case to defend against, but the outermost CLI boundary that's supposed to guarantee valid JSON output did not, until now. Fixed by adding except KeyboardInterrupt, returning a clean {"success": false, "code": "interrupted"} envelope, mirroring the placement and rationale of the existing except OSError/except Exception clauses. 1 new red/green test (confirmed failing dramatically against the pre-fix code -- the interrupt escaped even the test runner itself).
