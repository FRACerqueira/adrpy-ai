# Round-13's own multi-flag test was vacuous; missing-Round-segment sub-case was untested

**Front:** Test-Adequacy audit | **Severity:** Medium | **Resolution:** Direct | **Round:** 14

Two related test gaps, both confirmed by mutation. First: round 13's test_log_names_every_offending_flag_when_more_than_one_is_wrong_at_once asserted 'round' in str(error) and 'reopenwhen' in str(error), but the UsageError's own static message tail already reads '...(--front/--severity/--resolution/--round) or deferred (--reopenwhen)...' unconditionally -- both substrings are present regardless of what the dynamic '/--'.join(offending) part actually contains. Mutating that join down to offending[0] (naming only the first offending flag, the exact regression the test's own docstring says it guards against) still passed the full suite. Fixed by asserting the literal joined substring ('--round/--reopenwhen') instead, confirmed via red/green against the same mutation. Second: round 13's malformed-Round test uses a Round value that IS present, just non-integer ('5 (tentative)') -- it never exercises the sibling case where the Round segment is entirely ABSENT from an otherwise well-formed structured line (Front/Severity present, no '| **Round:** ...' at all). Mutating match.group(4) or '' to match.group(4) or '0' (silently defaulting a missing Round to 0 instead of failing closed) passed the full suite. Fixed with a dedicated test for the missing-segment case, confirmed via the same red/green cycle.
