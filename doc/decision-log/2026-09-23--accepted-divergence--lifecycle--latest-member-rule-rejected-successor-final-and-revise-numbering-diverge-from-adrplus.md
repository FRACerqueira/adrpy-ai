# three lifecycle rules diverge from AdrPlus on purpose: latest member only, rejected successor final, revise numbering

Checked against AdrPlus's own handlers. (1) AdrPlus requires the latest family member only in version and revise (VersionCommandHandler/ReviseCommandHandler); adrpy applies the latest-member rule to approve, reject, undo and supersede too. (2) AdrPlus's UndoStatusCommandHandler, version and revise only check for a Superseded member, so a rejected successor can be undone, versioned and revised; in adrpy it and its whole family are final. AdrPlus's reject does put the predecessor back (RejectCommandHandler.cs:186-194), and adrpy keeps that. (3) AdrPlus's revise numbers the new revision as the target's revision + 1, which always collided when branching off an older revision; adrpy numbers from the highest revision the version holds (D4b). All three decided by the project owner in Round 40, to close tool-only paths to inconsistent families (see only-the-latest-family-member-is-alive-and-a-rejected-successor-ends-its-line).
