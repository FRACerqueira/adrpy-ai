# Whitespace-only --summary/--front silently write a blank/corrupted heading, and the same gap reaches new --title and supersede --domain

**Reopen-when:** the new project-wide free-text-field-validation audit front runs, or any of this project's free-text CLI flags gains a blank-after-strip check directly

Round 15's Stability pass found that `adrpy log`'s free-text fields are validated only for forbidden delimiters (`reject_embedded_delimiter`, which rejects `|` and line breaks), never for being blank/whitespace-only after normalization.

`--summary "   "` (three spaces) passes `parse_flags`'s empty-string check (it is non-empty) and `reject_embedded_delimiter` (no forbidden characters), so `build_entry_content` writes `"#    "` as the entry's heading line. `_parse_entry` then reads it back as `"#    ".lstrip("#").strip()` -> `""` -- the entry is written successfully, with no error and no warning, and is silently indexed in `INDEX.md` with a blank Summary cell forever. `--front` has a milder variant of the same bug: `"   "` collapses to a single stray space (`" "`) rather than empty, due to `_FRONT_SEVERITY_RE`'s greedy backtracking.

Checking whether this was `adrpy log`-specific, per the pre-release-audit skill's 'close the class, not the instance' rule, found it is not: `new --title "   "` creates a file literally named `ADR001V01-   .md` (spaces in the filename), and `supersede --domain "   "` writes the same blank domain to its header silently. The same root cause -- a free-text field checked only for forbidden delimiters, never for blank-after-normalization content -- plausibly reaches most of the CLI's free-text flags (title, domain, scope, front, summary, reopen-when), not just `adrpy log`.

**Why deferred, not fixed now:** the user decided this warrants a new, wider-scope audit front covering free-text-field validation across the whole project, rather than a narrow fix inside `log.py` alone -- fixing only `adrpy log`'s instance here would repeat the exact 'close the instance, not the class' mistake rounds 12-14 already made once on this same command. Before that front starts, the `audit-stability` and `audit-test-adequacy` agent definitions and the `pre-release-audit` skill were updated (same day) to require a sibling search at the point each finding is discovered, and to trigger a scope-boundary re-check when a finding's root cause is a reusable pattern that plausibly extends beyond the round's own confirmed scope -- both synced to their canonical source at C:/Sources/EA4AI.
