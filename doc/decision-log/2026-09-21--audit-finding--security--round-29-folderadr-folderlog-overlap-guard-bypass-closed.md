# 3 confirmed bypasses of the folderadr/folderlog containment guard closed (.. traversal, case-insensitivity, backslash separator)

**Front:** Security audit (round 29, 8th pass -- pre-release audit, angle: Security, corroborated independently by the same round's Test-Adequacy angle) | **Severity:** High | **Resolution:** Direct | **Round:** 29

Round 29's Security pass and Test-Adequacy pass, run independently in parallel with no shared context, both found and live-reproduced the same class of bug via different specific cases: ADR007V01's mutual containment guard (config-folderadr-folderlog-overlap, core/config.py) compared folderadr/folderlog via PurePosixPath(...).parts, a pure string-component comparison that never collapses '..'/'.' , never splits on a backslash separator, and is always case-sensitive -- none of which match real Windows/macOS filesystem semantics. 3 independently-confirmed bypasses, each verified live to resolve to the identical or a genuinely nested real directory on disk: (1) folderlog='doc/other/../adr' vs folderadr='doc/adr'; (2) folderlog='DOC/ADR' vs folderadr='doc/adr' (case); (3) folderlog='doc\adr\sub' vs folderadr='doc\adr' (backslash separator). Live end-to-end impact confirmed by the Security pass: with a bypassed config, adrpy new + adrpy log corrupt the same physical directory (an ADR file misrecognized as an unrecognized decision-log entry, log-index-regeneration-failed). Fixed via a comparison-only normalization (_normalized_repo_path_parts: os.path.normpath + Path(...).parts + .casefold() per component), used ONLY for the overlap decision -- the field's own STORED/displayed value is never changed, preserving this project's established forward-slash convention (confirmed by a dedicated regression test after an earlier implementation attempt that DID normalize the stored value broke 22 existing tests, escalated to and resolved by the project owner: comparison-only, not storage-changing). Case-folding is unconditional regardless of the current host OS, per the project owner's own explicit choice -- a config can be authored on one OS and used on another, so host-conditional case-sensitivity would validate against the wrong platform's semantics. Close-the-class search: grepped the whole src/ tree for PurePosixPath/.parts usage -- this was the only string-based containment comparison in the codebase; every other containment check (resolve_within/is_within in core/security.py) already does real filesystem-based resolution (Path.resolve()), which handles all 3 vectors by construction. No sibling instances found. Mutation-verified: reverted to the vulnerable PurePosixPath(...).parts form, confirmed the 3 new regression tests fail for the predicted reason (DID NOT RAISE), restored, confirmed green. 4 new tests added to test_config.py (3 new parametrize cases on the existing overlap test, 1 dedicated comparison-only-not-storage test). Suite: 1019 passed, 3 skipped, 1 xfailed, 0 failed.
