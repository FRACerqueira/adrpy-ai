# An AGENTS.md block crossing another skill's block is now malformed, so --force never deletes that other block

**Front:** Round 37: hash-marker front (Low), re-verified live during round close | **Severity:** Medium | **Resolution:** Escalated | **Round:** 37

The hash-marker front reported (Low) that nested or overlapping blocks of different skills were not detected as malformed, calling it unreachable by normal use and self-correcting. Reproducing it live during round close showed the second claim does not hold: the outer skill reads as 'drifted', and install --force on it replaced its whole span, silently deleting the inner skill's block (nested) or leaving that skill with an orphaned end tag, i.e. malformed (overlapping); the warning named only the forced skill. Still only reachable by hand-editing, and the lost block is regenerable by reinstalling it. Same invariant as 2026-09-22--audit-finding--skills--agentsmd-force-cleanup-and-regex-dos-closed.md (Round 34, High): --force on one skill never touches another skill's block. The project owner chose to fix it rather than accept it as a documented risk. Fixed in 182ddb6: a shared _agentsmd_own_tags rejects a span containing any other skill's tag, used by both _agentsmd_skill_span and _agentsmd_extract_inner. Red/green: both shapes, plus a positive control (adjacent blocks with no blank line) that stays clean. describe(), doc/skills/install.md, remove.md and README.md name the new malformed shape.
